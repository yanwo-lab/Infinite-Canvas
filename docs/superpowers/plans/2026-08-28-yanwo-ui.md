# Yanwo UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete roadmap Phase 7 with a removable repository-local UI plugin that gives built-in and plugin nodes a coherent professional workspace presentation without changing workflow data or interaction semantics.

**Architecture:** Add `plugins/yanwo-ui/` as a normal discovered plugin. Its ES module uses the Phase 6 toolbar slot for a small status/control surface, while its independently loaded stylesheet supplies scoped visual tokens and state styling for the existing Smart Canvas DOM. Core files change only if a stable generic hook is proven necessary by a failing behavior test.

**Tech Stack:** Browser ES modules, CSS, Node.js built-in test runner, existing Python plugin discovery.

**Spec:** `docs/CODEX_ROADMAP.md` sections 13, 18, and 19.

## Global Constraints

- Do not change Canvas JSON, node type, connection, plugin execution, or existing Loop semantics.
- Do not migrate built-in nodes into plugins or add core `node.type` special cases for plugin nodes.
- Prefer CSS in `plugins/yanwo-ui/style.css`; use only the formal Phase 6 UI extension facade from JavaScript.
- Removing or failing to load Yanwo UI must leave Smart Canvas functional.
- Do not introduce a frontend framework or any new dependency.
- Preserve Docker static-file and plugin-discovery compatibility.

### Task 1: Removable Yanwo UI workspace presentation

**Files:**
- Create: `plugins/yanwo-ui/plugin.json`
- Create: `plugins/yanwo-ui/index.js`
- Create: `plugins/yanwo-ui/style.css`
- Create: `tests/yanwo-ui.test.mjs`
- Modify only if a failing behavior test proves necessary: `static/js/plugin-host.js`, `static/js/smart-canvas.js`, `static/smart-canvas.html`, `static/css/smart-canvas.css`

**Interfaces:**
- Consumes: `activate(host)`, `host.registerToolbarItem(definition)`, repository plugin discovery, existing `.image-node`, `.plugin-node`, `.node-port`, selection/running/error/unknown classes.
- Produces: manifest id `yanwo-ui`, a toolbar item owned by `yanwo-ui`, and a stylesheet scoped by existing Smart Canvas selectors with no workflow-state mutation.

- [ ] **Step 1: Write failing behavior tests**

Add a discovery-boundary test that reads the manifest and confirms `main: "index.js"` and `styles: ["style.css"]`, then call Python `discover_plugins()` in the Phase verification to confirm generated static URLs.

- [ ] **Step 3: Implement the minimal plugin**

Create a valid API v1 manifest, an `activate(host)` function that registers the toolbar item without reading Canvas internals, and a scoped stylesheet that:

- establishes a dark professional workspace surface while respecting existing theme variables;
- gives built-in and plugin node shells a consistent border, elevation, header/body hierarchy, hover and selection treatment;
- keeps List, For Each, and IF named ports visible and distinguishable;
- styles running, success, error, disabled, unknown-plugin, and group states using existing classes/attributes;
- improves create-menu and toolbar information hierarchy without changing their DOM or event behavior;
- includes reduced-motion and narrow-viewport fallbacks.
